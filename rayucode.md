## Vibe Booking — AI Booking Concierge

### Architecture
A **FastAPI microservice** (port 8001/4009) implementing a stateful, purpose-built conversational booking concierge for Cambodia travel. NOT a general-purpose chatbot — every fact comes from backend tool calls.

**High-level flow:**
```
Client ──WebSocket──▶ API Layer ──▶ Agent Core (tool loop) ──▶ Model Layer (LLM)
                                       │                      ──▶ Tool Layer (15 tools)
                                       └──────────────────────▶ Session Layer (Redis)
```

**Key components:**
- `main.py` — FastAPI entry point with lifespan management (Redis init/close, Sentry, CORS)
- `api/websocket.py` — WebSocket endpoint with auth, rate limiting, message routing
- `agent/core.py` — Async tool loop orchestration (the heart of the agent)
- `agent/tools/_defs.py` — 15 tool schemas + dispatch map
- `agent/backend_client.py` — HTTP client to NestJS backend with circuit breaker
- `agent/session/` — Redis-backed session persistence
- `agent/models/` — Pluggable LLM client layer (Gateway/Ollama)
- `agent/prompts/` — System prompt construction
- `agent/suggestions.py` — Follow-up chip generation
- `agent/blurbs.py` — Per-card description generation

### Session Management

**State model** (`agent/session/state.py` — Pydantic `BaseModel`):
```python
class ConversationState(BaseModel):
    session_id: str
    user_id: str
    is_authenticated: bool
    messages: list[dict]       # OpenAI-compatible format
    preferred_language: str     # "EN" | "KH" | "ZH"
    last_active: datetime
    created_at: datetime
    next_seq: int               # Monotonic turn counter for archive
    pending_archive: list[dict] # Turns awaiting persistence
    archived_seq: int
    message_seq: dict[str, int] # message_id -> seq mapping
```

**Persistence** (`agent/session/manager.py`):
- Redis key: `session:{session_id}`
- TTL: 7 days (604800 seconds)
- Messages capped at 60 (model sees last 20)
- Saved after every turn

**Additional features:**
- Rate limiting: 10 messages/minute per session (Redis-backed, keyed by verified user ID or client IP)
- Postgres archive integration via `agent/session/archive.py` (fire-and-forget background tasks)
- Session hijack protection: existing authenticated sessions cannot be claimed by another user
- Guest-to-authenticated rebind support (reattaches archived transcript)

### Communication

#### Backend Communication (`agent/backend_client.py`)
- **HTTP client:** `httpx.AsyncClient` with 15s timeout
- **Base URL:** `{BACKEND_URL}/v1/`
- **Auth:** `X-Service-Key` header (validated: 32+ chars, entropy check)
- **Localization:** `Accept-Language` header (maps internal "KH" → backend "km")
- **Circuit breaker:** Opens after 5 failures, cooldown 60s. Does NOT trip on 4xx (user errors).
- **Error handling:** Returns structured `{"success": False, "error": {...}}` responses; never raises
- **Singleton pattern:** Module-level `_client` with `get_backend_client()`

### Notable Patterns

1. **Async Tool Loop** (`agent/core.py`) — Two variants: `run_agent()` (simple) and `run_agent_streaming()` (yields events for WebSocket). Loop constraints: max 5 tool loops, last 20 messages, 2048 max tokens. Iterates until `end_turn` or no tool calls.

2. **Content Payload Builder** — `build_content_payloads()` maps ALL tool results to typed frontend blocks (trip_cards, hotel_cards, guide_cards, transport_options, weather, budget_estimate, qr_payment, booking_summary, custom_trip_card, etc.). Auto-derives `map_view` from card coordinates.

3. **Security-First Design** — JWT verification (HS256) fails closed; session hijack detection & blocking; input sanitization (injection pattern regex, max length); server-side user_id injection for mutations; auth-gated tool execution (defense in depth at both loop and execution layer); payment verification never trusts client claim.

4. **Resilience Patterns** — Circuit breaker on backend calls; LLM retry with exponential backoff (429/5xx); streaming fallback to non-streaming; graceful degradation for suggestions/blurbs; emergency contacts hardcoded fallback (safety invariant).

5. **Map Coordinate Derivation** (`agent/tools/geo.py`) — Backend trip responses lack coordinates — `lookup_coords()` matches known Cambodia destination names in text to approximate city centers for map rendering.

6. **Post-Answer Enrichment** — After the main answer, runs `generate_suggestions()` + `attach_card_blurbs()` concurrently (25s timeout). Both are tool-less model calls with heuristic fallbacks.

7. **Structured Logging** — Uses `structlog` for JSON logs with token counts, latency metrics, and session IDs.

8. **Prometheus Metrics** (`api/health.py`) — Exposes `/metrics` with: `active_connections`, `messages_processed_total`, `tool_calls_total`, `errors_total`, `response_time_seconds`.

9. **Model Client Abstraction** — `ModelClient` ABC with `GatewayClient` (OpenAI-compatible) implementation. Factory pattern with singleton management. Khmer language always routes to Gateway.

10. **Backend Locale Mapping** — Internal codes EN/ZH/KH mapped to backend en/zh/km. KH (agent) → km (backend) translation handles the mismatch.

### Common Infrastructure (`src/common/`)

**Guards** (registered globally in `common.module.ts` as `APP_GUARD`, in order):
1. `CustomThrottlerGuard` — runs first so even 401s consume quota; keyed by IP or hashed service key; bypasses itself under Jest; fails open on Redis outage.
2. `JwtAuthGuard` — Passport JWT; `@Public()` opts out.
3. `RolesGuard` — coarse `users.role` claim from JWT via `@Roles()`.
4. `AdminRoleGuard` — DB-backed `admin_users` grant via `@AdminRoles()`; cached 5m in Redis; SUPER_ADMIN passes everything.

Plus `ServiceKeyGuard` (per-route, for `/v1/ai-tools/*`).

**Throttler**
- Single `default` throttler registered; per-route override via `@RateLimit('AUTH'|'PAYMENT'|'WRITE'|'SERVICE'|...)` presets in `rate-limit.ts`. `NoRateLimit()` for Telegram webhook.
- `RedisThrottlerStorage` — atomic Lua `INCREMENT` script (check-and-increment is atomic, preventing burst); replaces the library's per-process Map.

**Interceptors**
- `TransformInterceptor` — wraps responses as `{ success, data }` (skips if already wrapped).
- `LoggingInterceptor` — single status-leveled Pino line per request; 5xx→error, 4xx→warn, else→info.

**Filters**
- `PrismaFilter` — P2002→409, P2025→404, P2003→409, P2023→400.
- `AllExceptionsFilter` — catch-all, returns `{ success: false, error: { code, message } }`.

**Cache**
- `CachedService` — cache-aside `getOrSet` over Redis.
- `CacheInvalidationService` — pattern-based invalidation for trips/hotels/guides/vehicles/search; never throws.

**Decorators** — `@Public()`, `@CurrentUser([claim])`, `@Roles()`, `@AdminRoles()`, plus `@RateLimit`/`NoRateLimit`.

**Errors** — central `ErrorCode` const-tree (~90 codes by domain: AUTH, VAL, BKNG, PAY, etc.).

**i18n** — `parseAcceptLanguage` reads `Accept-Language`, supports `en|zh|km`.

**DTOs/Types** — `ListQueryDto` (shared pagination + q/lang/sort), `ApiResponse<T>` envelope type.

### API Conventions

- **Prefix** `/v1/` applied globally; never redeclare in `@Controller()`.
- **Envelope** `{ success, data, message, error }` — `TransformInterceptor` wraps success; filters wrap errors.
- **Auth**: Bearer JWT; service-to-service via `X-Service-Key`.
- **Validation**: `forbidNonWhitelisted: true` — every query param must be declared in the DTO or the request 400s.
- **Naming**: `feature.controller.ts`, `feature.service.ts`, `feature.dto.ts`.
- **Refresh tokens** only in Redis; `refresh_tokens` table is not written to.
- **Paginated admin handlers** must return the service result directly so the interceptor nests `meta` inside `data`.
- **Naming**: route params are UUIDs via `ParseUUIDPipe`.

### Notable Patterns

1. **Use-case classes per handler** — handlers delegate to injected use-case classes (e.g., `ListTripsUseCase`, `BookGuideUseCase`) rather than embedding logic in services; DTOs carry input, use-cases orchestrate.
2. **Global guard chain with opt-out** — auth/role/throttle guards are global; routes opt out with `@Public()` and opt into role checks with `@Roles()`/`@AdminRoles()`. A route without `@AdminRoles()` is NOT admin-protected.
3. **Distributed rate limiting via Lua** — atomic increment-and-classify in Redis, shared across instances; fails open on Redis outage.
4. **Catalogue cache-aside with broad pattern invalidation** — reads cache through `getOrSet`; admin writes invalidate whole families (e.g., `cat:trip:*`) because query-hash keys can't be reconstructed from an entity id.
5. **Polymorphic booking model** — `BookingItem` links to trip/hotel-room/vehicle/guide via nullable FKs with a frozen `snapshot` JSON for cancellation fidelity.
6. **Out-of-band ABA settlement** — ABA payments settle from a Telegram credit alert matched by amount; ambiguous matches deliberately settle nothing.
7. **BigInt serialization** — `drivers.telegram_id` is bigint; `main.ts` sets Express's `json replacer` to stringify BigInts (Telegram IDs exceed `Number.MAX_SAFE_INTEGER`).
8. **`rawBody: true`** — load-bearing so the Stripe webhook controller can verify the exact bytes Stripe signed.
9. **Throttler-under-Jest bypass** — detected via `JEST_WORKER_ID`; overridable with `THROTTLE_IN_TESTS=true`.
10. **Hand-written migrations** — prefer `migrate deploy` over `migrate dev`; generate candidate SQL with `prisma migrate diff` and review before applying. Seed via `npm run prisma:seed` (idempotent, dependency-ordered).

### State Management

Three Zustand stores in `store/adminStore.ts`:

| Store | Purpose | Persisted |
|-------|---------|-----------|
| `useAuthStore` | User, token, auth status, permissions, role checks | Yes (`derlg-admin-auth`) |
| `useNotificationStore` | Real-time notifications (BOOKING, DRIVER_STATUS, EMERGENCY, SYSTEM) | No |
| `useUIStore` | Sidebar collapse state | Yes (`derlg-admin-ui`) |

**Hydration gate:** The auth store uses `persist` with `onRehydrateStorage` to sync the token into localStorage after rehydration. `AdminLayout` waits for `_hasHydrated` before rendering, preventing flash-of-unauthenticated-content.

**Permission model:** `hasPermission(permission)` and `hasAnyRole(roles)` derive access from the user's `adminRole`/`permissions`. `SUPER_ADMIN` bypasses every check. The `usePermission()` hook (in `hooks/usePermission.ts`) exports convenience booleans (`canManageDrivers`, `isSuperAdmin`, etc.) used to gate sidebar items and in-page actions.

**Server state:** TanStack Query (React Query) handles all API data, with WebSocket events triggering targeted `invalidateQueries` calls.

### API Client (`lib/api.ts`)

A single axios instance configured with:
- **Base URL:** `${NEXT_PUBLIC_API_URL}/v1` (default `http://localhost:4007/v1`)
- **Credentials:** `withCredentials: true` (sends the httpOnly `derlg_refresh` cookie)
- **Request interceptor:** Injects `Authorization: Bearer <token>` from localStorage (`admin_access_token`)
- **Response interceptor:** Unwraps the backend envelope `{ success, data }` → `data`

**Pagination helper:** `unwrapList<T>(response)` normalizes both paginated `{ data, meta }` and bare-array responses into `{ items, meta }`.

### Architecture

#### High-level
The admin panel is **frontend-only**. Its API lives inside the main NestJS backend at `/v1/admin/*` (no standalone backend service). The stack is: Next.js 16 SPA → REST `/v1/admin/*` + WebSocket `/v1/admin/ws` → NestJS backend → PostgreSQL (Prisma) + Redis (pub/sub) + MinIO.

#### Architecture diagrams (`docs/architecture/`)
Two files:
- **`admin-architecture.md`** — 11 Mermaid diagrams: system context, driver assignment flow, Telegram real-time status sync, emergency alert flow, dashboard composition (8 parallel queries), auth & token refresh, Telegram bot system architecture, driver registration, real-time driver status, trip assignment with Telegram notification, and broadcast messaging flow.
- **`admin-system-design.md`** — system design document.

#### Design system (`app/globals.css`)
Shares tokens with the public site so both read as one product:
- **Neutrals:** Zinc scale (`neutral-0` → `neutral-950`)
- **Accent:** Mekong teal (`accent-50` → `accent-900`) — primary actions only
- **Status:** success, warning, danger, info
- **Dark-first** with light mode via `.light` on `<html>`

#### Backend integration map
Each frontend route maps 1:1 to a backend controller (e.g. `/admin/bookings` → `admin-bookings.controller.ts`). The sidebar nav mirrors `@AdminRoles()` decorators exactly — the backend is the source of truth for authorization.

### Notable Patterns

1. **Role-aware navigation as a mirror of backend guards** — `AdminSidebar.tsx` nav items carry a `roles` array that duplicates backend `@AdminRoles()` decorators. The sidebar is the backend authorization model in miniature; if they drift, users see links that 403.

2. **Soft-delete everywhere** — Drivers, vehicles, and guides are referenced by historical bookings, so the API exposes `deactivate` endpoints (never DELETE). Several comments document past 404s from calling DELETE where no handler existed.

3. **Dual-payload shapes handled defensively** — WebSocket `AdminEventPayload` and `dispatchAdminEvent` accept both camelCase and snake_case keys, because Redis publishers are a mix of admin services (camelCase) and Telegram handlers (snake_case).

4. **Hydration-gated render** — `AdminLayout` renders a spinner until `_hasHydrated`, preventing premature redirect and flash-of-unauthenticated-content.

5. **Thin pages, fat components** — Route `page.tsx` files are minimal shells; all domain logic lives in feature components under `components/admin/<domain>/`.

6. **Generic DataTable** — A single reusable `DataTable<T>` with sort, filter, pagination, loading skeleton, and empty states, used across all list views.

7. **Recursive event dispatch** — `ADMIN_EVENT` catch-all unwraps inner events and re-dispatches (up to `MAX_UNWRAP_DEPTH = 3`), so new backend events need no matching frontend case.

8. **Auth split** — Access token in localStorage (`admin_access_token`), refresh token in httpOnly cookie (`derlg_refresh`). The 401 interceptor refreshes with a plain `axios.post` (not the `api` instance) to avoid recursive 401 handling.

9. **Dev affordances** — Login page has a "Dev Login (no backend)" button creating a mock SUPER_ADMIN session for local UI work; `SEED_ADMIN_PASSWORD` uses a documented dev fallback when blank.

10. **Testing** — Jest 30 + Testing Library, jsdom environment, with `jest.setup.ts` mocking `matchMedia`, observers, `crypto.randomUUID`, `localStorage`, `Notification`, and `AudioContext`. Coverage threshold 50%.

### Notable Patterns

1. **Envelope unwrapping at the boundary** — `request<T>` unwraps the backend's `{ success, data, error }` envelope so callers get `T` directly; Zod parses every response so backend changes surface at the call site, not as deep `undefined`s.

2. **Locale-first cache keys** — every React Query key starts with the locale so switching language never serves stale localised content. Bookings are the exception, scoped by token owner.

3. **BFF for service-key protection** — `AI_SERVICE_KEY` never reaches the browser; `/api/ai/*` proxies attach it server-side, enforce an allowlist, rate-limit, and derive `user_id` from the verified JWT (never trusting the client).

4. **External stores via `useSyncExternalStore`** — session, theme, and currency are module-level external stores read without a setState-in-effect cascade. Access token lives in memory only (XSS-resistant; refresh is httpOnly).

5. **Framework-agnostic, testable core** — `VibeSocket`, `transcriptReducer`, and `deriveWorkspace` are pure/React-free with no socket or React dependencies, so frame sequencing and workspace derivation are unit-testable in isolation.

6. **Idempotency-keyed writes** — booking creation mints one idempotency key per mount, reused across retries (prevents double holds), refreshed on success.

7. **Payment settlement by polling, not trust** — `usePaymentStatus` polls the backend (the authority) rather than trusting the browser to declare success; `useStartPayment` never confirms. Sandbox `confirm` is deliberately without a UI caller.

8. **Defensive Zod parsing** — `looseObject` for provider-shaped/evolving payloads, `.nullish()` for explicit-null fields, filter interfaces without index signatures to keep excess-property checking.

9. **Schema divergence modelled honestly** — field names are NOT normalised across entities (e.g. `coverImageUrl` vs `coverImage`); presentation code picks the right field, so backend changes don't hide.

10. **Typed WebSocket protocol** — inbound frames are validated against a discriminated union before reaching the UI; the agent's output is treated as untrusted input, with close codes driving distinct reconnect behavior.
